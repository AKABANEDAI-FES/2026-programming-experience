# Issue #22 キオスク設定の確認手順

## 適用範囲

受付・制作画面（ホーム、お絵かき、プログラミング、完了）で常時有効です。
大画面用の /display では有効化しません。展示モード切替や管理者画面は追加していません。

- ブラウザ標準とBlockly独自の右クリックメニューを抑止します。
- F5、Ctrl+R、Ctrl+Shift+R（Cmd+Rも含む）を抑止します。
- F12、Ctrl+Shift+I/J/C/K、Cmd+Option+I/J/C/Kを抑止します。
- メニューキーとShift+F10も抑止します。
- 通常の入力、コピー・貼り付け、Undo、削除、左クリックは制限しません。

## 起動

リポジトリのルートで実行します。

```powershell
npm install
npm run dev
```

http://localhost:5173 を開きます。

## 当日使うブラウザでの手動確認

1. ホーム、描画キャンバス、プログラミング画面の背景・ブロック・入力欄で右クリックし、メニューが開かないことを確認します。Shift+F10とメニューキーも確認します。
2. 絵を描いた後とブロックを置いた後に、F5、Ctrl+F5、Ctrl+R、Ctrl+Shift+Rを押し、画面と作品が保持されることを確認します。
3. F12とCtrl+Shift+I/J/C/Kを押し、開発者ツールが開かないことを確認します。入力欄にフォーカスした状態でも確認します。
4. 描画、消しゴム、Undo、次へ、ブロックの追加・移動・ゴミ箱への削除、セリフの日本語入力・文字削除・コピー・貼り付けができることを確認します。
5. 放流、完了表示、5秒後のホーム復帰を確認し、復帰後も制限が有効なことを確認します。
6. /display を別タブで開き、この制限が適用されていないことを確認します。

## 放流トークンの設定（前日・当日の朝）

受付・制作画面ではF12などで開発者ツールを開けないため、放流トークンは制限のかからない /display で設定します。
保存先のlocalStorageは同じサイトなら共通なので、/display で設定すれば制作画面でも使われます。

1. 普通のChrome（ゲストモード・シークレットウィンドウは使わない）で /display を開き、F12で開発者ツールを開きます。
2. コンソールで次を実行します。

   ```js
   localStorage.setItem('programming-experience-release-token', '<Worker に設定したトークン>');
   ```

3. PCを再起動し、もう一度 /display のコンソールで次を実行して、トークンが表示されることを確認します。

   ```js
   localStorage.getItem('programming-experience-release-token');
   ```

4. 確認できたら、同じプロフィールのChromeでキオスクモードを起動します。

当日の朝も、各PCで3の確認をします。再起動で内容が元に戻るソフトが入ったPCや、終了時にサイトのデータを消す設定のブラウザでは、トークンが消えるので注意してください。
トークンはチャットやドキュメントに貼らず、担当者から口頭か紙で受け取ります。

## 制約と開発中の操作

Webページが受け取れるイベントを抑止する機能です。ブラウザの再読み込みボタン、
メニューからの開発者ツール起動、アドレスバーにフォーカスした状態のキー操作、
Alt+Tab等のOS操作までは禁止できません。Firefox系のShift+右クリックなど、
ページにcontextmenuイベントを通知しない操作もあります。
当日のブラウザで確認し、端末全体の制限が必要ならOS・ブラウザのキオスク設定を併用してください。

開発時に再読み込みや開発者ツールが必要な場合は、ブラウザのボタン・メニューから操作します。
